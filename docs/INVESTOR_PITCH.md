# POP-UP CUBE — 투자자 미팅 브리프

> **용도:** 투자자·대표님 미팅 시 참고용 (기능 시연과 함께 사용)  
> **작성 기준:** 2026-07-13 제품·사업 방향 (`HANDOFF_POPUP_STORE.md`, AD-028/029/030/031 반영)  
> **포지션:** 게임 회사가 아니라 **「실물을 파는 온라인 팝업스토어」** — 게임 요소는 체류·재방문·SNS 확산을 위한 **보조 장치**

---

## 1. 한 줄 요약

**POP-UP CUBE**는 브랜드·점주가 **오프라인 팝업과 비슷한 공간**을 온라인에 만들고, 소비자가 **캐릭터로 들어가 구경·채팅·쇼핑**하며 **실물 상품을 구매**하는 플랫폼입니다.  
멀리 사는 사람·기간을 놓친 사람도 **「팝업에 왔다」**는 경험과 **실제 배송**을 동시에 얻습니다.

## 2. 왜 지금인가 — 문제

| 오프라인 팝업의 한계 | POP-UP CUBE의 답 |
|---|---|
| 기간·장소 한정 | 링크 하나로 전국·전 세계 접근 |
| 줄·혼잡·이동 비용 | 24/7, 거리 이슈 없음 |
| 「한 번 가본 사람」 위주 | SNS·아바타로 **온라인 과시·재방문** |
| 자사몰은 「목록 쇼핑」 | **공간·분위기·한정 이벤트**로 「팝업」 경험 |
| 메타버스는 디지털 소비 중심 | **실물 주문·배송·점주 주문 관리**까지 연결 |

## 3. Roblox·Zepeto·일반 쇼핑몰과의 차이

| | 일반 쇼핑몰 | 게임형 메타버스 | **POP-UP CUBE** |
|---|---|---|---|
| 핵심 | 구매 편의 | 가상 세계·플레이 | **경험 + 실물 구매** |
| 수익 | GMV | 가상 아이템·광고 | **실물 GMV + 점주 SaaS·패키지** |
| 과시 | 리뷰·인증샷(수동) | 가상 스킨 | **산 실물 → 아바타·디지털 연동 과시** |
| 점주 | 템플릿 스토어 | 맵 제작 난이도 높음 | **점주 툴로 팝업 분위기 꾸미기** |
| 한정·이벤트 | 쿠폰 | 시즌 패스 | **할인 vs 가챠 증정(선택형 프로모션)** |

**한 문장:**  
> 「가상에서만 노는 게 아니라, **진짜 산 것**을 가상에서도 뽐내고, 그 과정이 **팝업처럼 재밌다**.」

## 4. 소비자 경험 (데모에서 보여줄 흐름)

1. 홈에서 **팝업스토어(월드)** 선택 → 입장  
2. **2D 픽셀 공간**에서 이동·다른 방문자와 **실시간 채팅**  
3. 매장 안 **상품 보기 → 장바구니 → 배송지 선택 → 결제(mock·추후 PG)**  
4. 구매 완료 후 **혜택 선택:** 확정 **할인** 또는 **가챠 증정**(아래 §6 상세)  
5. (로드맵) 구매한 실물과 연동된 **아바타·디지털 아이템**으로 SNS식 과시  

**투자자에게 강조할 포인트:** 결제·주문·배송지·점주 주문 관리까지 **이미 DB에 실제로 쌓이는 구조** — 「게임 데모」가 아니라 **동작하는 커merce 플랫폼」.

## 5. 점주·브랜드( B2B ) 가치

- **매장 만들기** — 이름·대표 이미지·설명·픽셀 월드(데모: 탑뷰, 정식: 에디터 확장)  
- **상품 등록·주문 관리** — 실물 SKU, 재고·배송 연동 전제  
- **프로모션** — 할인율·가챠 풀(실물 상품 + 한정 디지털 증정품)  
- **간접 체험** — 오프라인 팝업을 온라인에 **비슷하게** 재현 → 멀리 있는 고객·기간 놓친 고객 포착  

**초기 GTM(시장 진입):**  
- 스토어 **직접 영업**으로 입점  
- **마케팅 비용 아끼지 않음** — 플랫폼 단독 유입보다 **입점 브랜드가 자체 팬·SNS로 유입** + 플랫폼 마케팅 병행  
- 카테고리 **집중**(예: 패션·굿즈·K-브랜드) 후 확장

## 6. 가챠 구조 — 「도박」이 아닌 이유 (핵심 논리)

### 6.1 우리 서비스의 실제 구조 (AD-028, 제품 반영)

```
[1] 소비자가 실물 상품을 정가(또는 정상 거래)로 구매·결제
         ↓
[2] 구매가 완료된 뒤, 「이벤트성 리워드」를 형태만 선택
         ├─ A. 할인 — 확정적 혜택 (예: 10% 할인 반영)
         └─ B. 가챠 — 확률형 「증정품·사은품」 (추가 금액 없음)
```

**중요:**  
- 가챠를 **「돈을 내고 돌리는」** 구조가 **아님**  
- **이미 발생한 구매**에 대한 **사후 선택형 프로모션**  
- 「할인 받을지, 사은품 뽑기로 받을지」 — **추가 과금 없음**

비유:  
- 백화점 **「구매 금액별 사은품」**  
- 편의점 **「1+1 / 증정 이벤트」**  
- 길거리 **「구매 후 캡슐 증정」** (뽑기 **자체에 돈을 내는 것**과 다름)

### 6.2 일반적인 「도박·사행」 논의와의 차이 (설명용)

| 구분 | 전형적 사행(도박)에 가까운 구조 | **POP-UP CUBE** |
|---|---|---|
| 돈의 목적 | **확률 결과 자체에 베팅** | **실물 상품 구매**가 목적 |
| 추가 과금 | 베팅금·재화로 **추가 추첨** | 구매 **이후 추가 금액 없음** |
| 손실 | 베팅금 **전액 손실** 가능 | **구매한 실물은 이미 확보** (증정은 보너스) |
| 선택 | 없거나 강제 | **할인(확정) vs 가챠(증정)** 소비자 **선택** |
| 성격 | 재화·현금의 **재분배** | **마케팅·CRM·재방문** 목적의 **증정** |

→ 구조상 **「돈을 걸고 확률로 더 벌거나 잃는다」**가 아니라  
**「이미 한 구매에 붙는 이벤트 혜택을 어떤 형태로 받을지 고른다」**에 가깝습니다.

### 6.3 「그래도 도박성 아니냐?」에 대한 **정직한 반론(리스크)** — 미팅에서 선제 답변용

아래는 **반대편에서 나올 수 있는 논리**입니다. 숨기지 않고 **「우리는 이렇게 막는다」**로 연결하는 것이 투자자 신뢰에 유리합니다.

| 가능한 반론 | 우리의 대응 |
|---|---|
| **「상품 가격에 가챠 비용이 숨어 있지 않나?」** | 가격은 **매장·브랜드가 명시**하고, 증정 풀은 **마케팅 예산·원가 범위**에서 운영. **가격 인상 = 가챠용** 구조를 플랫폼 정책으로 **금지·모니터링** 가능. |
| **「사실상 가챠 때문에 산다」(실질)** | 구조는 **구매 후 선택**. **가챠만을 위해 0원에 가까운 더미 SKU** 같은 어뷰징은 **약관·점주 가이드**로 차단. |
| **「확률형 = 청소년·표시 규제」** | **확률·당첨 풀 공개**, 미성년자 **구매·프로모션 정책**, 브랜드별 **옵트아웃(할인만)** 지원. |
| **「가챠 전용 아이템이 현금성·거래성 있으면?」** | 디지털 증정품은 **과시·컬렉션** 목적, **P2P 현금 거래·환금** 구조는 **하지 않음**(AD-020 소유권 모델). |
| **「브랜드 법무가 확률 마�eting으로 분류」** | **「구매 연계 증정 이벤트」** 문구·약관·UI 고정. 필요 시 **할인만 쓰는 매장** 허용. |

**결론(미팅용 한 줄):**  
> 「가챠에 **추가로 돈을 쓰는 것**이 아니라, **이미 산 실물 구매에 대한 사은품을** 할인으로 받을지, **뽑기 형태의 증정**으로 받을지 **고르는 것**이다. **길거리 뽑기방에 돈 넣고 돌리는 구조와 다르다.**」

※ 최종 법률 판단은 **변호사·공정거래/표시광고 검토** 권장. 본 문서는 **투자·사업 설명용 논리 정리**이며 법률 자문을 대체하지 않습니다.

## 7. MZ·SNS 과시와의 연결

- **실물 구매** → **한정 디지털 배지·아바타 연동** → **캡처·공유**  
- 오프라인 **한정판 인증샷**을 **플랫폼 안에서** 반복 가능  
- **「나 이 팝업 갔고, 이거 샀어」**를 온라인 정체성으로 표현  

→ **체류 시간·재방문·입점 브랜드의 SNS 확산**으로 이어지는 **마케팅 레버**.

## 9. 현재 제품 상태 (데모, 2026-07-13 기준)

**동작 중:**  
- 로그인(소비자/점주)·홈 허브·매장 입장  
- 2D 탑뷰 월드·멀티플레이·채팅

**데모 후 정식:** PG 실결제, draft/publish 매장, 풀 에디터, 아바타·픽셀 파이프라인(AD-020)  

**데모 데이터:** 정식 전환 전 §30 절차로 **DB 테스트 데이터 일괄 초기화** 가능 (스키마·코드 유지).

## 10. 투자자에게 보여줄 「3분 시연」 순서

1. 소비자 로그인 → 홈 → **GUCCI(또는 입점) 팝업** 입장  
2. **걸어 다니며** 채팅·다른 접속자 확인  
3. **상품 담기 → 장바구니 → 배송지 → 결제(mock)**  
4. **할인 vs 가챠** 선택 → 결과  
5. (점주 계정) **주문 관리**에서 방금 주문·배송지 확인  
6. 한 줄 마무리: **「게임이 아니라, 팝업에 와서 **실제로 주문**까지 되는 쇼핑몰입니다.」**
